# 0.1.1 启动闪退修复与 Android 测试环境

日期：2026-10-18。

## 已复现的问题

用户报告 0.1 安装后启动闪退。此前只有构建、lint 和纯逻辑测试，未运行真正的 Activity 启动，这是验证缺口。

本次在 Android 14（API 34）AOSP x86_64 模拟器上安装原始 release APK，两次冷启动均失败：

```text
java.lang.IllegalArgumentException:
No initializer set for given class com.haoqi.training.ui.training.TrainingViewModel
at androidx.lifecycle.viewmodel.internal.ViewModelProviders.createViewModelFromInitializers
```

原始 APK SHA-256：`C4A79B6BA2B0A4B64CFD01D2DEF6162FF6FD612A35F245C84B5AB0B36E1248E0`。

## 根因和最小修复

`appViewModelFactory(create: (AppContainer) -> ViewModel)` 把具体 VM 类型擦成基类。
Lifecycle 的 `initializer` 用泛型类型作为工厂注册键，因此注册到了 `ViewModel`，而调用方请求 `TrainingViewModel`，找不到对应初始化器。

改为 `inline <reified VM : ViewModel>`，创建函数返回 `VM`，并显式调用 `initializer<VM>`。三个页面的 ViewModel 均通过这一处修复，未绕过初始化或捕获后吞掉异常。

版本升级为 `versionCode=2` / `versionName=0.1.1`。包名及签名保持一致；模拟器上使用 `adb install -r` 从原版覆盖升级成功，不要求清除数据或卸载。

## 测试环境

- 已存在 JBR 21、Android Emulator 37.1.11 和 ADB；JDK 不在 PATH，用明确路径设置 JAVA_HOME。
- Windows WHPX 加速检测通过，未安装新驱动、未更改虚拟化设置。
- 从 Google 官方源下载命令行工具及 API 34 AOSP x86_64 系统镜像，并验证官方 SHA-1。
- 测试 SDK、AVD、下载和运行日志放在项目 `.android-test/`，已加入 gitignore。
- AVD：`CuriousTrainingApi34`；序列号 `emulator-5556`；无窗口模式。

```powershell
# 从项目根目录启动（前台长期进程，可在独立终端运行）
.\scripts\start-android-test.ps1
# 安装后执行冷启动回归
.\scripts\startup-smoke.ps1 -Serial emulator-5556
# 实际 UI 层级操作（需要 Python 3）
python .\scripts\ui-smoke.py --adb "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
```

冷启动脚本 force-stop 后重新启动 Activity，等待启动协程执行，检查进程、前台 Activity 和 crash buffer；失败时退出 1 并保留日志。不使用 `am start` 的 Status: ok 作为唯一成功标准，因为原版虽打印 ok，随后仍然崩溃。

首次通知权限弹窗会使 Activity 非最顶层，需要先在模拟器选择允许或拒绝，再执行上述严格前台断言。脚本兼容 API 34 dumpsys 的 `topResumedActivity`/`ResumedActivity` 字段。
