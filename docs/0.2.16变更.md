# 0.2.16 撤销恢复组状态、到点必响、静音可提醒、崩溃日志

## 一、撤销「这一天练完」时，把所有黑色组恢复成白色

**原因**：`setDayCompleted(false)` 只改了当天的完成标记，`set_states` 里已经点过的组还是 done，撤销后仍显示黑色，得一组一组手动取消。

**改法**：`TrainingRepository.setDayCompleted` 在 `completed == false` 时，同事务执行
`UPDATE set_states SET done = 0 WHERE exerciseId IN (SELECT id FROM exercises WHERE dayId = ?)`。

**验证**：把一组、二组点黑 → 点「完成」→ 点「撤销」→ 再点第一组、第二组，两组都能重新开始计时（说明状态确实回到了未完成）。

## 二、到点必响：闹钟改为广播接收器 + 系统闹钟通知

**原问题**：通知栏里的倒计时会一直走到负数，只有重新打开 App 才补响。原因是到点靠
`AlarmManager` + `PendingIntent.getForegroundService` 拉起前台服务；在澎湃 OS 上进程被冻结/杀掉后，
系统会拦掉后台启动前台服务，闹钟「静默失败」，直到 App 回到前台 `ensureSynced()` 才发现已超时。

**改法**：

1. 精确闹钟改为投递到清单里注册的 `RestAlarmReceiver`（广播不依赖前台服务，也不受 FGS 启动限制）；
2. 接收器判断服务是否还在正常走秒（`lastTickElapsed` 心跳）：
   - 还在走 → 交给服务自己收尾（保留 6 秒铃声、按电源键/划通知停铃的体验）；
   - 已冻结/被杀 → 直接震动 + 发一条走**闹钟音频通道**（`USAGE_ALARM`）的「休息结束」通知，
     系统负责播放声音，进程再被回收也不影响；
3. 两种收尾用 `RestTimerStore` 的 `alerted_at` 去重，同一轮休息不会响两遍；
4. 接收器会 `stopService` 掉残留的「休息中」前台服务，通知栏不会再出现负秒数。

**验证**：开始 30 秒休息 → 回到桌面 → `kill -9` 进程 → 32 秒后通知栏出现「休息结束，开始下一组」，
且通知所属通道是 `rest_timer_alert_v1`（闹钟音频通道），没有残留「休息中」通知。

## 三、静音模式下也能响、能振动

- 结束提醒的通知走**闹钟音频通道**（`AudioAttributes.USAGE_ALARM`）：手机调静音（铃声/通知静音）时，
  闹钟音量通道仍然会发声；这是 Android 上「静音也要响」的唯一系统级做法。
- 震动由 App 直接调 `Vibrator`（不是依赖通知的振动开关），静音模式下同样有效。
- 限制：**勿扰模式**里如果关掉了「允许闹钟」，系统仍会拦掉声音/震动，需要用户在勿扰设置里允许闹钟；
  另外闹钟音量调到 0 时也不会有声音。

## 四、闪退排查：崩溃日志 + 后台启动前台服务降级

- 新增 `CrashLogger`：未捕获异常写入 `filesDir/last_crash.txt`，下次启动弹窗展示（可复制/清除）。
  个人自用没有崩溃平台，下次再闪退时把弹窗截图发来即可定位。
- `startForegroundSafe` 增加兜底：系统不允许后台起前台服务时退化成普通通知并停止服务，不再把异常抛到主线程。
- 顶部天数标签的自动滚动加了 `runCatching`，避免测量未完成时滚动异常导致闪退。

> 闪退根因尚未在真机抓到（模拟器连续 6 次锁屏/解锁 + 杀进程冷启动都没有复现）。0.2.16 先把崩溃日志带上，
> 下次复现后按日志修。
