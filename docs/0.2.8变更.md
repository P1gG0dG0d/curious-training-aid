# 0.2.8 动作拖动排序与划掉通知停铃

## 需求

1. 长按动作卡片后可以上下拖动，调整动作顺序，要有顺滑动画；此前只能按创建顺序排列，无法调整。
2. 铃声响起时，把「休息结束」通知划掉应该立即停止响铃，此前必须按电源键。

## 改动

### 拖动排序

- 训练日页由普通可滚动 `Column` 改为 `LazyColumn`，每个动作卡片按 `exercise.id` 作为 key。
- 长按 500ms 触发拖动（带震动反馈）：被拖卡片放大 1.5%、抬高阴影、跟随手指移动；其他卡片用 `Modifier.animateItem()` 平滑让位。
- 拖动过程中只改本地顺序，松手后一次性把该天的新顺序写入数据库（`exercises.orderIndex` 从 0 重排，只影响这一天）。
- 列表顺序来自数据库，重启后保持新顺序。
- 空列表、`添加动作`、`删除这一天` 也变成列表项，随内容一起滚动。

### 划掉通知停止铃声

- 原因：结束提醒此前用前台服务通知（`startForeground`）发出，前台通知**系统不允许划掉**，而且没有 `deleteIntent`，所以划掉既不生效、铃声也不会停。另外保持前台是为了防进程被回收。
- 现在铃声阶段先 `stopForeground(STOP_FOREGROUND_REMOVE)` 退出前台状态，再用 `NotificationManager.notify` 发普通通知；服务本身继续存活到铃声结束（6 秒）再 `stopSelf`。
- 通知加 `setDeleteIntent(ACTION_DISMISS_ALERT)`：划掉通知时服务收到该 action，立即停止铃声、取消震动、清除回调并结束服务。
- 震动器改为持有引用，`stopAlertSound()` 里一并 `cancel()`。

## 验证（Android 14 模拟器，`scripts/verify-v028.py`）

- 清空数据后新建 AAA、BBB、CCC 三个动作（休息 3 秒），顺序为创建顺序。
- 用 `input motionevent DOWN → 1 秒 → MOVE → UP` 模拟长按拖动，把 CCC 拖到最上方：界面顺序变为 CCC、AAA、BBB；`force-stop` 后重启仍是 CCC、AAA、BBB，说明已落库。
- 点组块仍能正常开始计时（拖动没有抢走点击）。
- 等待 3 秒后结束通知出现；展开通知栏对它横向滑动：
  - 滑动后 `dumpsys notification` 中不再有「休息结束」通知；
  - `dumpsys activity services` 中 `RestTimerService` 已销毁（铃声停止路径与 `onDestroy` 都会停声）。
- 拖动过程中的截图确认被拖卡片抬起并带阴影，其余卡片让位。
- 32 项 JVM 单元测试通过，release 构建通过。

## 限制

- 未在物理手机上验证手势手感与 MIUI 通知划动行为；模拟器与实际 ROM 的触摸、动画帧率可能有差异。
- 仅支持同一天内排序；跨天拖动未实现。
- 长按并拖动会先经过 500ms 长按判定，期间手指不要抬起。
