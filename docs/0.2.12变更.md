# 0.2.12 按名称与份量自动估算营养

## 需求

手动录入/编辑食物时，名称与份量可以由用户改；改了之后热量与三大营养素应该跟着 AI 重新估算。但用户如果自己改过这些数字，就不再覆盖。

## 行为

- 弹窗里改「食物名称」或「份量」→ 去抖 800ms 后调用一次 AI（纯文本，无需照片），把热量 / 蛋白质 / 脂肪 / 碳水填进去。
- 任何一次手动修改这四个数字中的任意一个 → 之后不再自动调用，也不再覆盖；提示行会说明当前状态。
- 未配置 API Key 时提示「未自动估算：未配置 AI，无法自动估算，请手动填写」，原有数值不动，仍可手填保存。
- 模型返回明显不合理的数值（热量 > 10000 kcal 或营养素超出常识范围）时整体丢弃并提示手填，避免把离谱数字写进记录。
- 提示行固定高度，切换状态时弹窗不会跳动。

## 实现

- `ai/DeepSeekClient.kt`：新增 `estimateMacros(config, name, portion)`，文本提示要求只输出 JSON；多项结果求和合并成一条，并做合理性校验。
- `ui/diet/DietViewModel.kt`：新增 `MacrosEstimate` 状态与 `estimateMacros()`（去抖 + 取消上一次请求）、`clearEstimate()`。
- `ui/diet/DietScreen.kt`：编辑弹窗跟踪「用户是否动过数字」，`LaunchedEffect(name, portion, numbersEdited)` 触发估算，结果只在未手动修改时回填。

## 验证（Android 14 模拟器）

用本地假 AI 接口（`scripts/_fake-llm.py`，OpenAI 兼容，按份量返回营养）做端到端验证，避免真实计费：

| 步骤 | 结果 |
| --- | --- |
| 输入名称 `Rice` | 触发 1 次请求，营养素自动填入 |
| 份量由 `1 份` 改为 `200g` | 再次请求，数值变为 200 kcal / 蛋白 20 / 碳水 40 / 脂肪 10 |
| 手动把蛋白质改成 77，再改名称 | 不再发起请求，77 保持不变 |

脚本：`scripts/verify-v0212.py`；32 项 JVM 单元测试与 release 构建通过。

说明：端到端验证用的是 **debug 包**，因为 release 默认禁止明文 HTTP，而假接口跑在本机 `10.0.2.2`。`app/src/debug/` 下加了仅 debug 生效的网络安全配置（只放行 10.0.2.2 / 127.0.0.1 的明文），release 行为不变。

## 限制

- 自动估算依赖模型质量与准确度，结果仍是估算值；不同模型/服务返回差异较大。
- 每次改动名称或份量都会产生一次 API 调用（去抖 800ms），会消耗 token。
- 未在物理手机与真实 DeepSeek Key 上验证这条新链路（此前图片识别同样未实测）。
