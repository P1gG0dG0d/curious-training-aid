# 0.2.11 按电源键静音

## 需求

休息结束响铃时，按一下电源键就能安静：立即停铃、通知自动消失；点亮或息屏状态下都有效。

## 能做到与做不到

**能**：铃声一响就监听屏幕开关状态变化，检测到屏幕状态翻转（按电源键的必然结果）立刻静音、取消震动、去掉通知并结束服务。

**不能**：普通应用无法截获电源键，也无法阻止屏幕亮灭。电源键由系统（PhoneWindowManager）直接处理，`KEYCODE_POWER` 不会下发给应用；要真正「按键只静音、屏幕不动」需要无障碍服务过滤按键、设备管理器或 root，这些权限不经用户单独授予无法获得，且无障碍过滤电源键本身也不可靠。

所以实际效果是：**按一下电源键，铃立刻停、通知消失，但屏幕会照常点亮或熄灭一次**。

## 实现

- `RestTimerService` 在开始响铃时注册 `ACTION_SCREEN_ON` / `ACTION_SCREEN_OFF` 广播（`RECEIVER_NOT_EXPORTED`），响铃结束时注销。
- 收到任一个广播且仍在响铃 → `silenceAndDismiss()`：停铃声、取消震动、`STOP_FOREGROUND_REMOVE`、取消通知、`stopSelf()`。
- 划掉通知（`deleteIntent`）复用同一套 `silenceAndDismiss()`，行为一致。

## 验证

Android 14 模拟器（`scripts/verify-v0211.py`，干净数据 + 2 秒休息的动作）：

| 场景 | 结果 |
| --- | --- |
| 亮屏响铃，按电源键 | 铃停、通知消失、服务销毁；屏幕转为休眠（系统行为） |
| 息屏状态下响铃，按电源键 | 铃停、通知消失、服务销毁；屏幕被点亮（系统行为） |

32 项 JVM 单元测试与 release 构建通过。

## 限制

- 屏幕状态一定会跟着变一次，这是普通应用的边界；需真机再确认 HyperOS 下广播时序是否有延迟（模拟器上 2 秒内完成静音）。
- 若用户在响铃期间因为其他原因点亮/熄屏，铃声也会被静音，这是同一机制的副作用。
