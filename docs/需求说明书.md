# 「好奇训练」需求说明书（v1）

> 代号：CuriousTrainingAid ｜ 文件夹：`curious-training-aid` ｜ 包名：`com.haoqi.training`
> 文档状态：需求已与用户逐轮确认（共 17 项决策）并获准开工；v1 已实现，待真机验证（2026-10-18）。

## 定位

- 平台：Android（原生 Kotlin + Jetpack Compose + Material 3）
- 模式：单机自用，无需注册、无账号、无云端、数据只存手机本地（可分享给少量朋友安装）
- 界面：中文
- 目标用户：一个人自己用；不做社交、不做多人协作

## 技术选型

| 项 | 选型 | 说明 |
|---|---|---|
| 语言/UI | Kotlin 2.0.21 + Jetpack Compose + Material 3 | 沿用「好奇旅行」验证过的组合 |
| 数据库 | Room（SQLite） | 本地持久化 |

## 功能清单（v1）

### 1. 训练计划页

**计划结构**
- 用户自定义一个循环，循环天数 N（如 4 天），每天对应一个独立训练日。
- 每个训练日可建多个动作，每个动作包含：
  - 动作名称（自由文本）
  - 组数（如 4 组）
  - 休息时间（秒，每组做完后倒计时）
  - 容量：重量（kg）与次数**分开设置、分开保存**，统一应用于该动作所有组，不支持逐组不同。
- 无休息日概念：N 天全是训练日。

**界面交互**
- 顶部天数切换器：可点击选天，也可左右滑动切换；无日期绑定，纯手动推进。
- 动作列表：每行显示 名称 / 组数 / 休息 / 重量×次数。
- 组块：每个动作下 N 个方块，点一下表示该组完成并变黑；再点一下取消（v1 用「再点取消」，不做长按，误触成本低）。
- 点完一组后：自动进入该动作的休息倒计时（前台服务 + 通知栏倒计时 + App 内「休息中」横条，可手动跳过）；计时结束震动 + 响铃提醒。
- 每个训练日有明确的 **[完成]** 按钮：练习结束后由用户点击，标记该日完成。完成后该处显示「循环第n天已练完 ✓」，并允许撤销。
- **训练日没有顺序锁定**：任何一天都能直接练，不必先完成第一天；「第n天」只是计划编号，**不代表日期先后或时间顺序**。
- 完成状态不自动跳转，用户手动切换。
- 已完成状态与每组完成状态持久化，杀掉 App 重开仍在。
- **重量/次数记忆**：每个动作记住上次用过的重量×次数，下次打开预填，可修改。
- **不保存训练历史**：不记录“哪天练了什么”，只保存当前循环状态 + 上次重量/次数。

**边界**
- 完成后可随时回看/取消完成；取消后不影响其他天。
- 休息计时中可手动「跳过休息」提前结束。
- 循环全部天数完成后不自动重置，由用户手动处理（可再次点取消或修改计划）。

### 2. 饮食页

**每日总消耗（灰条）**
- 基础代谢 BMR：Mifflin-St Jeor 公式
  - 男性：`10×体重(kg) + 6.25×身高(cm) − 5×年龄 + 5`
  - 女性：同式 `− 161`
- 活动代谢：用户手动填写（kcal/天），长期有效，可随时修改。
- 总消耗 = BMR + 活动代谢。灰条长度 = 总消耗。

**摄入热量（蓝条）与 500 kcal 虚线**
- 蓝条长度 = 当天已录入饮食的热量总和。
- 两条共用同一横向 kcal 刻度，上下对齐（灰条在上、蓝条在下）。
- 竖虚线画在 `max(总消耗, 摄入) − 500` 处，穿过两个条；无论消耗大还是摄入大，规则相同：
  - 虚线落在**较短条的内部** → 差值不足 500 kcal；
  - 虚线落在**较短条末端之外** → 差值已超过 500 kcal。
- 摄入超过总消耗时不封顶，蓝条继续变长（如实显示超标）。

**营养结构（v1 简化）**
- 主界面只展示每日**总蛋白质、总碳水、总脂肪**摄入量，用柱状图表示。
- 每餐内的每条食物：折叠展示详情（热量 kcal、蛋白质 g、脂肪 g、碳水 g）。
- 不显示每日营养目标对比（v2 预留）。

**三餐结构**
- 固定早/午/晚三个分区 + 「加餐」分区（没加餐就不显示加餐区）。
- 每条记录：食物名、份量、热量、蛋白质、脂肪、碳水。

**录入流程**
- 手动录入：搜不到/不想拍照时直接填；填完可编辑、删除。
- 拍照识别：
  1. 拍照或选图；
  2. 图片发送至配置的 AI 接口（DeepSeek）识别食物及估算营养；
  3. 展示识别结果（食物名、估算份量、热量、蛋白质/脂肪/碳水），用户确认或修改；
  4. 确认后入账到对应餐次。
- 识别结果一律标记为「估算」，不伪装精确。
- 一张图片可识别多种食物。

### 3. 设置页

- 个人资料：性别、年龄、身高、体重、活动代谢。保存后饮食页顶部总消耗即时更新。
- AI 接口配置：Base URL（默认 `https://api.deepseek.com`）、模型名（默认 `deepseek-flash`）、API Key。
  - 「测试连接」按钮：调用 `GET /models` 校验 Key 与模型名，并检查模型是否支持图片输入；报错区分网络/Key 错误/模型不存在（地址不支持模型列表时退化为一次最小对话请求）。
  - Key 只存本机，不写日志、不进代码仓库；v1 存在 App 私有 SharedPreferences（未额外加密），`allowBackup=false`。
- 页面入口：底部导航两页（训练 / 饮食），设置放在标题栏齿轮图标。

## 数据模型（已实现）

| 表 | 字段（核心） | 说明 |
|---|---|---|
| `plans` | id、dayCount | 当前只允许一个计划（id=1）；id 预留多计划升级 |
| `plan_days` | id、planId、dayIndex、completed | 循环第几天、是否整日完成；外键级联删除 |
| `exercises` | id、dayId、orderIndex、name、setCount、restSeconds、weightKg、reps | 重量、次数独立存储，统一用于所有组 |
| `set_states` | id、exerciseId、setIndex、done | 每组完成状态；`(exerciseId, setIndex)` 唯一 |
| `food_entries` | id、date(yyyy-MM-dd)、meal、name、portion、kcal、protein、fat、carbs、estimated | 单条食物；按日期查询 |
| `profile` | id、sex、age、heightCm、weightKg、activityKcal、configured | 只有一份；`configured=false` 表示用户还没保存过资料 |

> 说明：不建 `ExerciseLastUsed` 表——重量/次数直接保存在动作上，本身就是「上次用过的值」；
> 不建 `DietDay` 聚合缓存——每日汇总按 `food_entries` 实时计算，避免缓存不一致。

**未来升级预留（v1 不做，但结构上不锁死）**
- Room `version` + Migration，新增表/字段不影响旧数据（已导出 schema、已写 v1→v2 迁移示例）；
- `plans.id` 而非单例，未来可多计划并存；
- 训练历史可另建 `WorkoutSession` 表，当前不建；
- 营养目标可加 `NutrientTarget` 表；
- v1 固定浅色主题（与「好奇旅行」一致），深色模式 v2 再考虑。

## 验收标准

训练页：
1. 能新建 N 天循环，每天独立添加动作（名称/组数/休息/重量、次数分开填）。
2. 点击组块变黑；点「完成」后显示「循环第n天已练完」，可撤销；杀进程重开状态保留。
3. 点完一组自动休息倒计时；锁屏/切后台仍继续；到时震动+响铃。
4. 重量/次数下次打开自动带出（保存在动作本身）。
5. 左右滑动 + 点击都能切换训练日；第 3 天不练第 1 天也能直接练。

饮食页：
1. 填身高体重性别年龄 + 活动代谢并保存后，灰条长度 = BMR + 活动代谢；未保存时提示先填资料。
2. 录入食物后蓝条增长、蛋白/碳水/脂肪柱状图更新、食物详情可折叠、可编辑删除。
3. 500 kcal 虚线位置符合「max−500」规则，两种大小关系都正确。
4. 拍照识别返回结果可修改后入账；断网/Key 错误有清晰提示且不崩溃。
5. 关掉 App 重开，当天记录还在。

## 风险与已知问题

- **JDK 未在 PATH**：`JAVA_HOME` 为空，构建命令必须显式设置 `JAVA_HOME=C:\Users\<用户名>\.jdks\jbr-21.0.11`。
- **DeepSeek 视觉接口**：官方文档确认 `deepseek-flash` 支持图像理解（base64 data URL）；识别时关闭思考模式（`thinking: {"type":"disabled"}`）以省 token、降延迟。
- **无模拟器镜像**：SDK 未装 system-images，锁屏计时、通知、震动响铃、拍照/相册只能靠真机验证。
- **前台服务常驻**：Android 12+ 需要 notification channel 与 `POST_NOTIFICATIONS` 权限；已在启动时申请，拒绝也能计时（只是看不到通知）。
- **AI Key 安全**：v1 用 App 私有 SharedPreferences，明文保存、不加密；已关闭系统备份。升级时可换 EncryptedSharedPreferences。
- **未验证项**：真实 DeepSeek 识别未用有效 Key 跑通（不代用户做付费调用）；真机 UI 细节（字体、间距、手势）待实测微调。
