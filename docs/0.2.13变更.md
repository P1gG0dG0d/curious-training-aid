# 0.2.13 改为保存时估算一次

## 调整

0.2.12 是「边打字边估算」（去抖 800ms），每次改名称/份量都会产生一次 API 调用。改成：

- 打字、改份量过程中**不调用** AI。
- 点「保存」时判断：**用户没有自己改过**热量/蛋白质/脂肪/碳水，且名称或份量与打开时不同 → 调用一次 AI，拿到结果后直接入账、关闭弹窗。
- 用户改过任意一个数字 → 按用户填的值保存，完全不调用 AI。
- 未配置 Key / 估算失败 → 弹窗不关闭，提示「自动估算失败：…」，可以继续手填后再次保存。
- 估算中按钮置灰并显示「正在估算营养并保存…」，避免重复提交。
- 估算出的热量为 0 或超出合理范围时不予采用，提示手填。

## 验证（Android 14 模拟器 + 本地假 AI 接口）

| 步骤 | 结果 |
| --- | --- |
| 只输入名称 `Rice`，不点保存 | 0 次请求 |
| 点一次保存 | 恰好 1 次请求，弹窗关闭，早餐出现 `Rice` 记录（碳水 0.2 g 等由接口返回） |

脚本：`scripts/verify-v0213.py`，32 项 JVM 单元测试与 release 构建通过。

## 限制

- 单独复测「手改数字后保存不调用 AI」这一步受自动化限制（kcal 输入框不会被 uiautomator 导出，坐标点击不稳定）。该守卫逻辑在 0.2.12 已端到端验证且本次未修改，真机上建议再确认一次。
- 估算结果仍依赖模型质量；每次保存最多 1 次 API 调用（原来可能多次）。
- 未用真实 Key 验证。
