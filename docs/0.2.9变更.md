# 0.2.9 编辑失效、通知文字与拖动阴影

## 1. 已创建的动作改不了（编辑是摆设）

**根因**：0.2.8 为支持拖动排序，在训练日页面里用 `var order by remember { mutableStateOf(exercises) }` 保存了一份本地顺序副本，并用
`if (exercises.map { it.id } != order.map { it.id }) order = exercises` 同步。这段判断只比较 **id 列表**：编辑动作时 id 不变，于是页面一直拿着旧的实体对象渲染，重量、组数、休息时间、名称全都显示改之前的值。数据库其实已经更新了。

**修复**：只要没在拖动，就用数据库的最新列表覆盖本地顺序（`if (draggingId == null) order = exercises`）。

验证：把 CCC 的重量从 20 kg 改到 42 kg、休息从 3 秒改到 60 秒，保存后卡片立即显示「42 kg」「1分钟」，`force-stop` 重启后仍是新值；再次打开编辑弹窗也带新值。

## 2. 通知栏看不到具体剩余时间

0.2.7 把每秒刷新通知文字改成了只依赖系统计时器（chronometer），但部分 ROM（含 HyperOS）的通知布局不显示这个计时器，只剩静态的「共 2分钟」，等于没有倒计时。

**修复**：两条路同时保留——
- 正文「剩余 X」恢复每秒刷新，任何机型都能看到具体时间；
- 仍保留 `setUsesChronometer` + `setChronometerCountDown`，App 被后台限流、文字更新被丢弃时由系统继续走秒。

验证：`dumpsys notification` 连续采样，正文由「剩余 59秒」变为「剩余 57秒」。

## 3. 拖动时卡片出现方形毛刺

**根因**：抬起效果加在包裹卡片的 `Box` 上，而 `Box` 比卡片本体宽（卡片左右各有 16dp 外边距），`graphicsLayer` 的 `shadowElevation` 按矩形绘制阴影，于是拖起来像一块方板。

**修复**：不再用 `graphicsLayer` 画阴影，改为给 `GroupCard` 增加 `shadowElevation` 参数，由 `Surface` 按 16dp 圆角绘制阴影；`Box` 只负责位移和 1.5% 缩放。抬起时阴影 12dp，落下恢复 0dp。

验证：模拟器拖动截图确认被拖卡片圆角完整、阴影柔和，不再出现方形边缘。

## 验证与限制

- 以上三项均在 Android 14 模拟器用脚本/截图核对；32 项 JVM 单元测试与 release 构建通过。
- 未在物理手机验证；HyperOS 的通知栏布局、手势手感仍需真机确认。
- 自动验证脚本 `scripts/verify-v029.py` 中「通知文字」一步偶尔因点击时机导致计时未启动而失败，属脚本时序问题；手动采样与成功运行均确认文字在走秒。
