# 好奇训练 · CuriousTrainingAid

一款免注册、离线优先的 Android 健身执行辅助 App，把「今天练什么、每组多重、组间歇多久、今天吃了多少」放进同一个入口。训练记录、休息计时和手动饮食记录可离线使用；可选的 AI 图片识别与连接测试需要联网。

- 作品名：好奇训练（CuriousTrainingAid），当前源码版本 0.2.9（versionCode 12）
- 队伍：5 队 · 我爱练腿队
- 队员：董昊奇、王子岩
- 赛道：校园生活
- 现场关键词：专注、信息获取、日程安排

## 一、解决什么问题

校园健身时，训练安排、组间计时、饮食记录往往分散在不同入口。本作品将它们集中到训练、饮食两个页面：用组块记录完成情况，用通知辅助休息计时，用当天热量和营养素汇总辅助回看。

训练日按循环组织，不绑定真实日期，也不限制必须依次完成；饮食按本地自然日记录。应用没有账号体系和云同步功能。

## 二、主要功能

### 训练

- 添加、删除训练日，至少保留一天；点击顶部未选中的训练日切换，点击已经选中的训练日可重命名，留空恢复「第 n 天」。也可左右滑动切换。
- 动作可设置名称、组数（1–20）、休息秒数（0–600）、重量和每组次数。重量、次数分别保存，统一作用于该动作的每组长按动作卡片可上下拖动调整顺序，松手后顺序写入本机，重启保持。
- 点击组块切换完成状态并保存；从未完成变为完成且休息时间大于 0 时启动倒计时。再次点击取消组完成状态不会自动停止已经开始的计时，应使用「跳过」。
- 前台服务提供应用内计时条和通知倒计时；通知正文显示「剩余 X」并每秒刷新，同时用系统计时器自行走秒，切后台或锁屏后数字仍继续减少。新计时会替换旧计时。结束时触发震动、播放系统闹钟铃声（约 6 秒后停止）并发出可划掉的结束通知；划掉该通知会立即停止铃声和震动，「跳过」停止计时并移除进行中的通知。
- 整日「完成」状态需手动标记，可撤销；它与各组完成状态分别保存。

### 饮食

- 总消耗估算 = Mifflin-St Jeor 基础代谢 + 饮食页当天填写的活动消耗。活动消耗按日期保存，新一天默认0；未配置个人资料时仅计已填活动，并提示基础代谢未计入。
- 摄入为当日记录之和，消耗和摄入共用同一 kcal 刻度。参考虚线位于 `max(0, max(消耗, 摄入) − 500)`；页面直接显示「消耗摄入差为：N 千卡（消耗 − 摄入）」。
- 蛋白质、碳水、脂肪各有汇总柱；早餐、午餐、晚餐支持手动录入，食物记录可展开、编辑、删除。
- AI 流程已实现为拍照/相册选图 → 上传识别 → 结果编辑 → 确认入账，记录标记「估算」。**尚未用真实有效 Key 验证完整图片识别链路，不能据此保证 DeepSeek 或其他服务可用。**
- AI 结果确认页可选择加餐；加餐区仅在已有加餐记录时出现，当前没有独立的首次手动添加加餐入口。
- 按本地日期统计摄入与活动消耗；持续前台约1秒内检查日期并切换，回到前台也会刷新。昨日数据保留，无历史日期浏览入口。跨日未保存的编辑需重新填写。

### 设置与 AI 配置

- 个人资料：性别、年龄、身高、体重，点击「保存资料」后用于计算。
- AI 配置：Base URL、模型名、API Key。源码默认地址为 `https://api.deepseek.com`、模型名为 `deepseek-flash`；这些是默认配置，不代表已实测的服务能力。Key 输入框为明文。
- 「测试连接」先请求 `GET /models`，核对模型名并读取 `input_modalities` 中的图片能力声明；字段缺失也会显示不支持看图。若服务返回 HTTP 404，则退化为一次最小文本对话请求，该请求可能计费。
- **连接成功不等于图片识别成功**：测试未实际发送图片，文本回退也不能验证视觉能力。兼容服务还需接受当前图片消息格式及 `thinking` 等请求参数，不能保证任意 OpenAI 兼容接口都可使用。

## 四、构建与安装

**Windows 注意：Android Gradle Plugin 会拒绝中文工程路径。** 解压后先将整个“源码”文件夹复制到全英文路径（例如 `C:\dev\curious-training-aid`），再在该目录执行以下命令；不要直接在中文作品包目录内构建。此限制已在实际验证中复现。

先设置 `JAVA_HOME` 指向自己的 JDK，并通过 `local.properties` 的 `sdk.dir` 或环境变量 `ANDROID_HOME` 配置自己的 Android SDK 路径。

```powershell
# 单元测试与调试包
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug

# Release 包（当前构建配置使用本机 debug 签名）
.\gradlew.bat :app:assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk

# 首次安装；覆盖安装仅适用于与设备已有应用签名一致的 APK
adb install -r app/build/outputs/apk/release/app-release.apk
```

首次构建需联网下载 Gradle 和依赖。源码不分发开发机的 `local.properties` 和本地签名私钥。当前 debug/release 都使用构建机器自己的 debug 证书；**另一台机器重新构建通常会使用不同证书，无法直接覆盖提交包中现有 APK 安装的应用**，`adb install -r` 不能绕过签名检查。可在另一设备或干净模拟器安装自建包；若选择先卸载旧包再安装，旧包本地记录和设置会丢失。

## 五、现场演示流程

基础演示不需要联网。首次启动如弹出通知权限请求，应允许通知，并检查系统通知与闹钟音量设置。下面数据仅用于演示。

1. **训练日**：首次打开训练页，默认有「第1天」。点击「添加一天」，新一天会自动选中；点击已选中的「第2天」打开命名弹窗，输入「练胸日」并保存。
2. **动作**：点击「添加动作」，输入名称「卧推」、组数 4、休息 15 秒、重量 60 kg、次数 8，保存后查看动作卡片。
3. **计时**：点击未完成的第一个组块，观察组块变黑、应用内休息条和通知。切到后台或锁屏查看通知，再返回；可等待到点查看结束提醒，也可在下一组计时期间点击「跳过」验证通知清除。设备通知和后台策略可能影响展示与提醒。
4. **完成与持久化**：点击训练日「完成」，查看「练胸日已练完」与「撤销」。结束计时后关闭并重新打开应用，回到该训练日检查动作和完成状态。
5. **饮食资料**：进入设置，填写男、23 岁、175 cm、70 kg，点击「保存资料」，返回饮食页，在「今日活动消耗」填写300并保存，查看总消耗估算。
6. **手动记餐**：点击「添加早餐食物」→「手动录入」，填「包子」、份量「100g」、热量 230、蛋白质 8、碳水 40、脂肪 4，点击「保存」。观察摄入条、营养素柱和直接显示的差值文案；点击食物行展开，再用编辑、删除按钮演示修改。营养素需要分别填写，不会由食物名称或热量自动推算。
7. **可选联网识图**：仅在已有可用服务并完成现场前实测时演示。设置 AI 地址、模型、Key 并保存，测试连接后，从某一餐的添加入口选择拍照或相册。选图后会发起上传；若返回结果，核对名称、份量、热量及营养素后「确认入账」。若失败，展示错误提示并继续使用手动录入，不把连接测试结果当成识图通过证据。

界面使用固定浅色主题，页面切换有过渡效果，没有换主题入口。

## 七、数据与隐私

- 训练记录、饮食记录和个人资料保存在本机 Room 数据库，当前源码没有将这些数据库记录同步到服务器的功能；API 配置另存于 App 私有 SharedPreferences。
- 配置 AI 后，主动拍照或选图会将压缩后的 JPEG（最长边至多 1024 px）和识别提示发送到配置的 AI 服务。**入账前确认只控制本地记录写入，不代表图片等到确认后才上传。**第三方如何保存或使用请求数据由其政策决定，本应用不能保证服务端不留存。
- 连接测试和图片识别都会向配置的服务发送 API Key 作为认证信息。Key 默认为空，本地存储未额外加密，输入时直接可见；配置时应使用可信的 HTTPS 服务。
- Manifest 设置 `allowBackup=false`，并提供排除备份/迁移的数据规则；没有应用内导出和恢复功能。卸载或清除应用数据会丢失本地记录与配置，不应把系统迁移当作数据恢复保证。

- 每次只有一个休息计时；取消组完成标记不会停止它。自然到点保留结束提醒，主动跳过才清除通知。
- 图表「达到 500 千卡目标」判断采用消耗与摄入差的绝对值，摄入高于消耗 500 kcal 也会显示达到；它不是个性化减脂建议，总消耗本身也只是公式估算。
- 只支持一套循环计划，没有按日期记录的训练历史、多计划、账号同步和趋势统计；当天饮食有记录，但界面没有历史日期查询。首次手动加餐入口尚未提供。
- 当前使用标准 Android 通知，没有接入小米 HyperOS「超级岛」。固定浅色中文界面，未做多语言；较多训练组块在窄屏上的展示仍需设备验证。
- 图标在不同启动器的裁切与圆形遮罩下可能有不同观感，不能保证与预览完全相同。
